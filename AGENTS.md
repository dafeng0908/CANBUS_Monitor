# AI Working Rules

## Allowed modification paths

AI may modify:

- firmware/NUCLEO-C542RC/App/**
- firmware/NUCLEO-C542RC/BSP/**
- firmware/NUCLEO-C542RC/tests/**
- tools/**
- docs/**

AI must not directly modify:

- firmware/NUCLEO-C542RC/Drivers/**
- firmware/NUCLEO-C542RC/Middlewares/**
- firmware/NUCLEO-C542RC/Core/Startup/**
- firmware/NUCLEO-C542RC/*.ioc

## Generated code rules

- Files generated by STM32CubeMX must not be rewritten.
- Generated files may only be edited inside USER CODE BEGIN / END blocks.
- Application logic must not be implemented inside generated interrupt handlers.
- Generated callback functions may only forward events to BSP or service modules.

## Architecture rules

- STM32 HAL headers may only be included by BSP modules.
- Application and service modules must not include stm32*.h.
- Application modules must not reference FDCAN_HandleTypeDef.
- Protocol modules must be compilable on a host PC.
- ISR code must not block, allocate memory, or call printf.

## Required workflow

Before changing code:

1. Read the active execution plan.
2. Identify affected modules.
3. State files expected to change.
4. Do not modify unrelated files.

After changing code:

1. Run python tools.py check
2. Run python tools.py architecture
3. Run relevant tests
4. Run python tools.py build
5. Update the active execution plan
6. Report commands, exit codes and report paths

## Forbidden behavior

- Do not report PASS without executing the command.
- Do not suppress warnings merely to pass a quality gate.
- Do not change public interfaces without updating tests and documents.
- Do not perform large unrelated refactors.
- Do not modify generated code to bypass architecture rules.

## Definition of Done

- Relevant code and documents are updated.
- Repository and architecture checks pass.
- Test and analysis results contain actual evidence.
- The active execution plan is updated.
